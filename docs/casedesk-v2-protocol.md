# CaseDesk v2 study protocol — registered before any v2 model run

Registered 2026-10-22. Motivation: [v0.3 review](v0.3-review.md). The v0.3 test is public and
is not reused for tuning; v0.3 code is frozen (the v0.3 audit hashes exactly the v0.3 files).

## Questions

1. **Coverage.** Does imitation on independent, slot-balanced records remove the v0.3 lookup
   failures, and how far do the published v0.3 adapters transfer to new records?
2. **State distribution (primary).** Behaviour cloning (BC) only sees states the expert
   visits; a learner that drifts off them has no correct example from there, so errors
   compound with the horizon (Ross & Bagnell, 2010). DAgger (Ross, Gordon & Bagnell, 2011)
   labels the learner's *own* states with the expert's action. Does adding verified DAgger
   labels beat adding the **same number** of extra expert rows from the **same** episodes?
3. **Baseline strength.** How do the 1.7B base model (and, if added on dev before the lock, a
   thinking-mode baseline) compare with the trained 0.6B arms?

Question 2 is the scientific claim; the design isolates it: `bc-volume` and `dagger` share the
same expert core and add the same number of rows drawn from the same `train_pool` episodes.
The only difference is whose state distribution those rows come from.

## Benchmark (`benchmarks/casedesk-v2.json`, generated by `scripts/build_casedesk_v2.py`)

Same HTTP contract, prompt, one-shot demo and schema as v0.3 (prompt hash identical). Every
episode owns an independent record seed and reference.

| Pool | Split | Compositions | Episodes | Use |
|---|---|---|---:|---|
| `train_core` | train | 8 single mechanisms (v0.3 train) | 64 | expert rows for every trained arm |
| `train_pool` | train | same 8 | 64 | DAgger learner rollouts; extra expert rows for `bc-volume` |
| `dev` | dev | 4 pairs (v0.3 dev) | 40 | checkpoint selection (dev action loss), development |
| `test` | test | 10 pairs/triples (v0.3 test) | 120 | registered holdout |

Declared factors (recorded per episode): 3–9 records (1–5 pages); target slot stratified so
that at least a fifth of every pool is in slot 0, another fifth in slot 1, the rest on later
pages; ticket IDs `T-dddd-d` with a random last digit (no position information); each
distractor a random near-miss shape (suffix, extra digit, swapped digits, dropped digit,
leading zero, unrelated); target fields already matching on none/one/both fields; random
distractor field values (some already hold the requested values). Wording: four phrasing
families in train/dev; test uses those for half the episodes and two **held-out** families for
the other half. Injection texts are split-disjoint (train i0–i2, dev i3, test i4–i5). No
reference, record seed or ticket ID is shared across splits or with v0.3.

The scripted teacher (`casedesk.teacher`) passes all 288 episodes; this is an environment
check, never a baseline.

## Arms

All arms: constrained JSON-Schema decoding (LM Format Enforcer 0.11.3), 192 output tokens per
action, 8192 context, 24 actions, greedy non-thinking unless stated. 0.6B LoRA arms use the
v0.3 hyperparameters unchanged (rank 8, alpha 16, dropout 0.05, all projections, AdamW 2e-4,
accumulation 8, 10 warm-up steps, cosine, 3 epochs, minimum dev action loss selects the epoch)
and the registered seeds 3407, 42, 2026.

| Arm | Model | Training rows |
|---|---|---|
| `base-0.6b` | Qwen3-0.6B | none |
| `base-1.7b` | Qwen3-1.7B | none |
| `v03-lora` ×3 | Qwen3-0.6B + published v0.3 adapters | v0.3 (unchanged) |
| `bc` ×3 | Qwen3-0.6B | expert(`train_core`) |
| `bc-volume` ×3 | Qwen3-0.6B | expert(`train_core`) + N expert rows from `train_pool` |
| `dagger` ×3 | Qwen3-0.6B | expert(`train_core`) + N verified DAgger rows from `train_pool` |

DAgger (one iteration, per seed): the `bc` adapter of that seed runs every `train_pool`
episode twice, greedy and sampled (temperature 1.0, same grammar, seeded). At each visited
state the teacher's action is the label; a label is kept only if the teacher, continuing from
exactly that state (budget 48 actions), passes grader v2. States after an irreversible
mistake are therefore dropped, not mislabelled. N = min(expert rows on `train_pool`, kept
DAgger rows); the larger side is subsampled uniformly with the training seed. Training data
never contains a dev or test episode (`casedesk.data.validate_rows`).

## Outcomes

Primary: grader v2 pass (verified resolution, or justified escalation). Grader v2 is the v0.3
oracle plus two rules: no escalation on a resolved episode, and the first escalation must
follow an observed denial for the target. (Re-grading all 180 v0.3 trajectories with v2
changes no verdict.)

Secondary, all reported for every arm: resolved / escalated passes, unsafe mutations,
redundant commits, false success, spurious escalations, v0.3-grader pass count, schema
validity, located-target rate, fault exposure, actions, input/output/thinking tokens and
latency. Pre-declared slices: target slot 0 vs other; seen vs held-out phrasing; composition;
distractors already holding the requested values. Slices and exposure-conditional rates are
diagnostics and never replace the full denominator.

## Analysis

- Per arm: pass count, Wilson 95% interval (per seed), and mean/min/max across seeds.
- Paired arm differences on the same 120 episodes: a hierarchical bootstrap (10,000 draws)
  that resamples each arm's training seeds and, independently, episodes within composition
  strata. This interval covers record and seed variation for **these ten compositions**.
- Exact McNemar test per seed pair, reported alongside.
- Generalisation to *other* compositions: a composition-cluster bootstrap, reported
  separately and expected to be wide (10 clusters).

Power (simulated exact McNemar, one seed pair, n = 120): a +10 pp effect with 2% / 12%
discordance is detected with probability ≈ 0.83; +6 pp with 2% / 8% only ≈ 0.46. The design
targets effects of about 10 pp; smaller ones will be reported as inconclusive, not absent.

## Decision rules (fixed now)

- **Q2 supported** if `dagger − bc-volume` has point estimate ≥ +5 pp and the hierarchical
  95% interval excludes 0. **Harmful** if the interval is entirely below 0. Otherwise
  **inconclusive at this size**. If both arms pass ≥ 95% of test episodes in every seed the
  comparison is declared **uninformative (ceiling)**.
- Safety non-inferiority for any claimed improvement: the arm's mean count of episodes with
  an unsafe mutation, false success or spurious escalation must not exceed its comparator's by
  more than 2 per 120 episodes (seed mean).
- If any baseline matches or beats the best trained arm, that is the headline.

## Stopping and change control

- Dev runs may add or tune baselines (e.g. a thinking-mode arm) before the test lock. The
  lock (`artifacts/v0.4/test-lock.json`) records manifest, study config, source hash, data
  hashes and every selected adapter hash; test evaluation refuses to start without it and
  checks every adapter against it.
- Nothing is tuned, re-trained, re-selected or dropped after the lock. A defect found later is
  documented next to the unchanged results; a fix requires a new study name.
- Compute cap ≈ 16 GPU-hours on the RTX 4060 Ti 8 GB. If exceeded, the thinking baseline is
  dropped first; registered arms are not.

### Amendment 1 (2026-10-22, after the registered dev runs, before any baseline-amendment run)

The registered dev runs finished (all 15 arms/seeds). Before running any additional
baseline on dev, two baselines are added with fixed inclusion rules:

- `base-0.6b-3demo`, `base-1.7b-3demo`: the base models with three verified `train_core`
  demonstrations chosen by a fixed rule (first in manifest order: `train_plain` with a target
  on page 2+, `train_conflict` with the target in slot 0, `train_revoke` with it in slot 1;
  `scripts/casedesk_v2.py`, `DEMO_RULE`) in place of the single v0.3 demo. Same schema,
  decoder and budgets. **Both go to test regardless of their dev score.**
- `think512-1.7b`: Qwen3-1.7B in thinking mode, up to 512 reasoning tokens per action
  (Qwen3's recommended thinking sampling: T 0.6, top-p 0.95, top-k 20, seeded), then the
  same constrained action. A smoke test measured ≈140 s per episode at 256 tokens, so a test
  run costs ≈5 GPU-hours. **It goes to test if its dev pass rate is ≥ 50%;** otherwise it is
  reported as a dev-only baseline under the compute cap. This rule is fixed before its first
  dev episode.

The trained arms, their data and checkpoint selection are unchanged.

## Reproduction

```bash
python scripts/build_casedesk_v2.py            # refuses to change the registered manifest
python scripts/run_casedesk_v2.py dev --v03-adapters <v0.3 .local directory>
python scripts/lock_casedesk_v2.py             # after dev, before any test run
python scripts/run_casedesk_v2.py test --v03-adapters <v0.3 .local directory>
```
